# DailyFit static support pages

Static support pages for the public `prxem-stack/privacy` GitHub Pages repository, in its `dailyfit/` subdirectory. Public routes:

- https://prxem-stack.github.io/privacy/dailyfit/
- https://prxem-stack.github.io/privacy/dailyfit/privacy.html
- https://prxem-stack.github.io/privacy/dailyfit/deletion.html

Publish this directory in the repository’s `dailyfit/` folder. Preserve existing repository-root files and other product policies. GitHub Pages serves the repository’s publishing branch. Keep the report service separate when updating this public site.

These are buildless HTML/CSS/SVG pages with relative internal navigation. No JavaScript, external fonts, analytics, account system, contact form, report-submission form, runtime secrets, backend or admin code are included. The support address is the existing public developer contact, `premharsh.official@gmail.com`. No phone number is published.

The 22 October 2026 policy covers DailyFit 1.1.0 local profiles and exclusions, routines/drafts, meal notes/checks, optional dated weights, mobile/browser model downloads, browser caching, video delivery and consent-based reports. Browser inference stays local; downloading model/runtime files contacts Hugging Face/jsDelivr. Public pages use GitHub Pages, whose security logs include visitor IP addresses. The separate report backend remains on OpenAI Sites/Cloudflare with consent, private review, receipt deletion and 90-day next-access purge. Do not move report API/admin routes or server secrets into this public repository.

Deletion instructions use the top profile icon and keep model removal and server-report deletion separate. Browser model removal does not promise to erase shared runtime files; browser settings can remove remaining files. The 27 adapted exercise videos are credited to Goulart/wger under CC BY-SA 4.0, with changes and no endorsement stated. Mobile assets are bundled; browser assets need internet on first load. These pages do not claim a public store release or verified native model compatibility.

The empty `.nojekyll` file is harmless in this folder. If the repository owner wants to disable Jekyll for the whole Pages source, that marker belongs at the publishing-source root; do not overwrite an existing root configuration solely for this subfolder.

Local validation checks HTML structure, local links/fragments, referenced assets and absence of scripts/forms/backend or secrets. Preserve all repository content outside dailyfit/. Verify deployed routes and mobile browser rendering after changes; static checks alone do not establish deployment success.
